## 2. Collection Method

1. Sparse, blob-filtered, shallow clone of the official repository:

```bash
git clone --filter=blob:none --no-checkout --depth 1 \
    --branch v3.11.9 https://github.com/python/cpython.git C:/tmp/cpython_clone
git sparse-checkout init --cone
git sparse-checkout set Doc LICENSE
git checkout v3.11.9
```

2. Checkout was repeated with `core.autocrlf=false` and `core.eol=lf` after the first
   checkout converted LF to CRLF. The first attempt was discarded, not modified, so the
   stored raw copy is byte-identical to the upstream blobs.
3. `Doc/` and the root `LICENSE` were copied verbatim to the raw destination; the source
   hierarchy, filenames and encoding were preserved.

Tag verification:

```
$ git describe --tags --exact-match HEAD
v3.11.9
$ git log -1 --format="%H %s"
de54cf5be371a6f5e2e9f208c38def5f81d3ef02 Python 3.11.9
```

## 4. License Information

Per https://docs.python.org/3.11/license.html, read in the collected `LICENSE` and
`Doc/license.rst`:

- Python software and documentation are licensed under the **PSF License Agreement
  Version 2** (`PSF-2.0`).
- Starting with Python 3.8.6, **examples, recipes and other code in the documentation**
  are **dual licensed under PSF-2.0 and the Zero-Clause BSD license** (`0BSD`). Python
  3.11.9 is therefore covered.
- Some software incorporated into Python carries different licenses. Those licenses are
  listed with the code falling under them.

Consequence applied to this collection:

- All 569 manifest rows record `source_license = PSF-2.0`.
- The dual `PSF-2.0 / 0BSD` status for embedded code examples is recorded in
  `license_notes` for every documentation file.
- Retention obligation recorded: keep the PSF copyright notice
  ("Copyright © 2001 Python Software Foundation; All Rights Reserved") and the license
  text with any derived material.
- The GitHub repository's own software license was **not** assumed to cover every
  document uniformly; per-file license notes were generated by scanning content.

### Files that mention additional licenses (reviewed in Phase 2B.1.1)

Four paths matched a licence keyword scan. They are **not** four files needing review:
review in Phase 2B.1.1 resolved three of them.

| File | Classification | Outcome of review |
|------|----------------|-------------------|
| `Doc/license.rst` | `PENDING_MANUAL_REVIEW` | PSF licence text (lines 1–295) plus an **appendix of third-party software licences** (lines 296–1098). This is the only file requiring manual review; excluded from the initial corpus until the appendix is split off or cleared. |
| `Doc/copyright.rst` | `ELIGIBLE_CANDIDATE` | Copyright page only (PSF / BeOpen / CNRI / CWI lines). The keyword hit was "All rights reserved"; no third-party material, no review needed. |
| `Doc/library/pprint.rst` | `ELIGIBLE_CANDIDATE` | The only licence tokens are incidental sample PyPI metadata (`'License :: OSI Approved :: MIT License'`, `'license': 'MIT'`) inside an example output. Not a licence grant; no review needed. |
| `Doc/tools/susp-ignored.csv` | `ASSET_NOT_TEXT` | Sphinx spelling-suppression word list, not documentation prose. Excluded as non-text, not as a licensing problem. |

No file was reclassified away from PSF-2.0. Only `Doc/license.rst` carries third-party
licence material; see `docs/PYTHON_DOCS_TRAINING_ELIGIBILITY.md` for the per-file
classification that downstream phases must follow.

## 9. Errors and Warnings

1. **Line-ending conversion on first checkout (resolved).** The first clone used Git's
   global `core.autocrlf=true`, which converted LF to CRLF in the working tree. This was
   detected before the manifest was written; the checkout was redone with
   `core.autocrlf=false`, `core.eol=lf`, and the raw copy was replaced. The stored files
   are now byte-identical to upstream blobs. **No data was altered by us — the conversion
   was a checkout artefact and was eliminated.**
2. **`Doc/make.bat` is CRLF by repository declaration.** Expected per CPython's
   `.gitattributes` (`*.bat dos`); verified by blob match after normalisation.
3. **68 non-`.rst` files were collected** as part of the `Doc/` tree (images, `.dat`,
   `.py` build helpers, `.html` templates). They are required to preserve the source
   hierarchy and are labelled `documentation_asset` in the manifest so they cannot be
   mistaken for training text. If a strict text-only corpus is preferred later, these can
   be excluded from preprocessing by filter rather than by deleting raw data.
4. **Third-party license appendix in `Doc/license.rst` only.** `Doc/copyright.rst` was
   reviewed and cleared (it contains no third-party material). The appendix in
   `Doc/license.rst` requires manual review before those passages are used.
5. **Tag is annotated, not a commit.** `git clone --branch v3.11.9` warns
   "refs/tags/v3.11.9 ... is not a commit"; the checkout resolved to the tagged commit
   `de54cf5`, confirmed by `git describe --tags --exact-match`.
6. No token counts are reported. Character and word counts are explicitly descriptive.
